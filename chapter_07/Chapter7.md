## Exercise 7.3
**Assume that in a new processor design, due to technical difficulty, the floating-point arithmetic unit that performs addition can only do “round to zero” (rounding by truncating the value toward 0). The hardware maintains a sufficient number of bits that the only error introduced is due to rounding. What is the maximal ulp error value for add operations on this machine?**

```text
Answer:
Number of representable numbers between intervals depend on the number of mantissa bits. Therefore, between 0 and 1 highest representable number that is smaller than 1 will be the error value for add operations. That approaches to a full ulp (units in the last place) and the bound is 1 ulp (at exactly 1 ulp away it would coincide with the next representable value, does not require truncation).
```


## Exercise 7.4
**A graduate student wrote a CUDA kernel to reduce a large floating point array to the sum of all its elements. The array will always be sorted with the smallest values to the largest values. To avoid branch divergence, he decided to implement the algorithm of Figure 6.4. Explain why this can reduce the accuracy of his results**

```text
Answer:
In the reduction loop, stride starts at blockDim.x. Since the array is sorted there can be significant exponent difference between the floating values. This causes shifting in mantissa bits and may introduce rounding error due to insufficient mantissa bits (part of the sum cannot be represented). Min-with-max pairing happens at the first and most impactful reduction level. If the student had instead used the algorithm in Figure 6.2, accuracy might have been higher, because with stride starting at 1, numbers of close magnitude get summed first.
```

## Exercise 7.5
**Assume that in a arithmetic unit design, the hardware implements an iterative approximation algorithm that generates two additional accurate mantissa bits of the result for the sin() function in each clock cycle. The architect decided to allow the arithmetic function to iterate nine clock cycles. Assume that the hardware fill in all remaining mantissa bits with zeroes. What would be the maximal ulp error of the hardware implementation of the sin() function in this design for the IEEE single-precision numbers? Assume that the omitted 1. mantissa bit must also be generated by the arithmetic unit.**

```text
Answer:
The IEEE single-precision mantissa requires 24 total bits (23 stored fraction bits + 1 implicit leading bit, which this hardware must also generate). At 2 accurate bits per cycle over 9 cycles, 18 bits are generated correctly, leaving the last 6 bits (weights 2^-18 through 2^-23) zeroed out instead of computed.

The maximal error occurs when all 6 missing bits should have been 1 but are forced to 0:

Error = 2^-18 + 2^-19 + 2^-20 + 2^-21 + 2^-22 + 2^-23

Expressed in ulp (1 ulp = 2^-23 for single precision), dividing each term by 2^-23:

= 2^5 + 2^4 + 2^3 + 2^2 + 2^1 + 2^0
= 32 + 16 + 8 + 4 + 2 + 1
= 63 ulp

Maximal ulp error = 63 ulp (equivalently, 2^6 - 1).
```
